# GitHub Pull Requests

Inspect the diff, base branch, existing PRs, tests, and required checks before
creating a PR. Use a descriptive title and body with summary, testing,
risks, rollout notes, and linked issues. Reuse an existing matching PR rather
than creating a duplicate. Push and PR creation/update require approval.
Merge readiness requires passing required checks, required reviews, no unresolved
conflicts, and explicit merge approval. Never bypass branch protection.

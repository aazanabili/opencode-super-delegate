# GitHub Releases

Inspect the latest release, tags, merged PRs, changelog convention, and CI
artifacts. Ask for an explicit version; do not infer or publish automatically.
Prepare release notes and a dry-run summary, then request release approval.
Tagging, pushing a tag, and publishing a GitHub Release are separate externally
visible actions. Verify the tag, release URL, assets, and release workflow after
publication. Never overwrite an existing tag or release without explicit scope.

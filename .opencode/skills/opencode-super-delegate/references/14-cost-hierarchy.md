# Cost-descending delegation tree

## Authority and work

| Tier | Typical work | Receives | Returns |
| --- | --- | --- | --- |
| L0 premium owner | Goals, budget/exception decisions, final acceptance | User intent, concise L1 evidence reports | Approved contracts and decisions |
| L1 cheaper leads | Project Plan, coordination, Clean Code/Security synthesis | Approved scope and policy indexes | Reconciled reports; targeted escalations |
| L2 cheaper specialists | Implementation, architecture analysis, focused review, correction | Bounded contract and applicable exact policy ranges | Task-local evidence and findings |
| L3 economical leaves | Searches, caller/test inventory, simple inspections | Precise question and narrow paths | Facts with locations; no delegation |

These are routing tiers, not fixed model brands or a requirement to launch four
layers. Use the shallowest economical tree. Planning also cascades: L1 delegates
requirements discovery/architecture alternatives to L2, which may use L3 for
fact gathering. Review leads independently delegate tests, security and quality
inspection. Neither a worker nor a lead may accept the final candidate.

## Allocation rules

Testing follows the same hierarchy: a cheaper L1 lead owns the coverage strategy
and result synthesis; authorized cheaper L2 test writers/runners produce persistent
tests and regression evidence. L3 helpers only inventory tests/callers. Reserve
their calls/resources in the shared budget and reuse valid evidence across gates.

- Prefer progressively cheaper models for downward edges, with sufficient tool
  and reasoning ability. Unknown prices must be disclosed; user-approved tier
  ordering can be used without claiming numerical savings.
- Do not delegate a tiny already-known answer when briefing/reporting costs more.
  Batch related mechanical questions; keep cohesive implementation contracts.
- Start with max depth 3 below L0, max children 3 per node, max total invocations
  12 per run, and max concurrent mutating tasks 1 unless the approved plan sets
  another finite bound. These are configurable ceilings, not target counts.
- Count retries, resumes, review re-runs and child calls against the run budget.
  Reserve capacity for verification and recovery; stop dispatch before depletion.
- Every child inherits the authorization ceiling, policy packet, requirement IDs,
  lineage counters and remaining shared budget. Children cannot mint new budgets.
- Track a DAG with parent IDs and immutable dependency versions. No ancestor
  re-invocation as a child, duplicate active tasks, or autonomous recursive skill
  loading. A leaf has `task: deny` and no CLI/process path to create descendants.
- A coordinator creates a child only on an approved role/model edge and with
  narrower responsibility. Reuse an existing result if inputs/evidence are valid.
- A costly failure may justify escalating to a capable approved intermediate
  model. Never keep work on a cheap model that repeatedly fails for capability
  reasons. L0 decides exceptions from the compact escalation, within user bounds.

## Cost accounting

Record calls, observed tokens/cost if exposed, estimates separately, elapsed time,
retries and coordination overhead by node. A local or prepaid model still has
latency/resource cost. Unknown monetary values remain null/unknown. Report savings
only against a defined measured or clearly labeled estimated baseline.

L0 normally loads only this module, the compact skill, routing and report contract.
L1/L2 read detailed policies/code and produce auditable evidence. L0 can request a
specific evidence excerpt when inconsistent or high-risk findings require it;
avoid automatically forwarding complete source files or transcripts upward.
